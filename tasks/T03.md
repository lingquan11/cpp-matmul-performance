# T03 扩大规模实测

- **线**：必做 | **计划用时**：4h | **前置**：T02 的预测已提交
- **一句话目标**：在 n = 256 → 2048 上测量 ikj 和分块，用数据回答 T02 的预测是对是错

## 步骤
1. 【me】新建 `src/matmul-scale.cpp`：用 `std::vector<int>` 按行主序存储（下标 `i*n + j`），支持运行时传入 n（最大 2048）。重写 `matmul_ikj` 和 `matmul_blocked(n, b)` 两个 kernel。不要修改 `src/day07-matrix-blocking.cpp`。
2. 【me】推导：按你的初始化方式，n = 2048 时 C 的最大元素会不会超出 `int` 的范围？把推导写进报告。会溢出就改用更小的输入值。
3. 【ai】计时框架：可以复用 `templates/gpt/scale-sweep.cpp`，也可以重写。要求每个配置先预热 1 次、正式测 5 次、取中位数，输出 CSV（n、算法、b、每次耗时、GOPS、校验结果）。GOPS = 2·n³ / 耗时（int 运算，不叫 GFLOPS）。
4. 【me】正确性：n ≤ 512 时与朴素 ijk 逐元素比较；n > 512 时分块与 ikj 逐元素比较。另测非整除的情况，例如 n = 1000、b = 64。
5. 【me】测量条件：接通电源，Windows 电源模式选"最佳性能"，关闭其他程序，用 `start /high /affinity <掩码>` 绑定到一个 **P 核**（掩码根据 T02 的 Coreinfo 结果确定）。把这些条件写进 `metadata.md`。
6. 【me】测量配置：n ∈ {256, 512, 1024, 1536, 2048} × {ikj, blocked_32, blocked_64}（可加 blocked_16），编译选项 `/O2`，与 T04 分开。
7. 【ai】作图：横轴 n，纵轴 GOPS，每个算法一条线。
8. 【me】报告 `experiments/reports/2026-MM-DD-scale-sweep.md`：结果表、图、与 T02 预测逐条对照（命中 / 落空，以及原因），最后写出 3 条局限。
