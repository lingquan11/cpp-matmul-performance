## O(n³)

讨论的是两个 n×n 方阵的朴素三重循环乘法。

- i 选择结果矩阵的一行，共 n 个值。
- 对每个固定的 i，j 选择结果矩阵的一列，取 n 个值。全部 i、j 组合有 n² 个。
- 对每个固定的 i、j，k 遍历 n 个乘积项并累加，得到一个结果元素。

最内层乘积累加的总次数：

T(n) 的主要项 = n × n × n = n³。

在一次乘法、加法及索引访问都按常数成本估计的模型下，朴素方阵乘法的时间复杂度为 O(n³)，也可写为 Θ(n³)。结果初始化是 O(n²)，不改变总体阶数。

每一层循环本身都是 n 次。n²、n³ 分别是跨外层累计后的组合数和最内层总次数。

矩阵边长从 n 翻倍为 2n 时：

(2n)³ / n³ = 8。

计算量变为原来的 8 倍。从 8 变为 64，是原来的 8 倍。这是计算量关系；实测耗时倍数在 `docs/report.md`。

## 性能实验方案（2026-10-23 拟定）

比较同一朴素乘法在不同矩阵规模下的运行时间。

| 项目 | 计划 |
|---|---|
| 矩阵规模 | 64×64、128×128、256×256 |
| 编译配置 | Release；记录编译器、版本和实际优化选项 |
| 测试环境 | 记录 CPU、操作系统、内存和电源模式，并尽量保持后台负载稳定 |
| 输入 | 使用固定且可复现的输入；取值避免所用数值类型溢出 |
| 预热 | 正式测量前先做不计入统计的预热 |
| 重复测量 | 每种规模正式测量 5 次，保留全部原始耗时并计算平均值 |
| 计时工具 | 单调时钟，如 C++ 的 steady_clock |
| 计时范围 | 矩阵乘法的计算部分 |
| 计时区间外的工作 | 分配内存、准备输入、清零结果矩阵、打印和正确性检查 |
| 正确性与优化检查 | 测量前后检查结果，并在计时后使用计算结果，避免计算被优化删除 |
| 统计与比较 | 统一时间单位，比较相邻规模的平均耗时比；波动保留在原始数据里 |

若程序采用累加写入 C，每次正式测量前清零 C。单次运算接近计时精度时，在样本内批量重复，并记录换算方式。

多次测量是因为后台任务和 CPU 频率会波动。保留每次结果，用来判断波动。平均值通常比单次更有代表性。

使用 Release 是为了测量打开编译优化后的运行情况，并把实际编译参数记下来。

cout 放在计时区间外，因为打印包含格式化和输出开销。测量目标是矩阵乘法计算本身。

边长翻倍时计算量变成 8 倍。实际耗时比还会受缓存、编译优化、系统负载和测量误差影响，用实验来看。
