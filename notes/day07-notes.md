# Day 7 学习笔记

今天我学习了分块矩阵乘法，并把 `ijk`、`ikj` 和三种分块大小放在同一个基准测试框架中比较。

分块不会改变矩阵乘法的数学定义。例如左上角结果子块需要计算：

`C00 = A00 * B00 + A01 * B10`

分块主要是重新组织计算顺序，让正在使用的数据有更多机会留在缓存中并重复利用。

我理解了为什么要使用 `min(ii + block_size, n)` 这样的边界处理。以 `n=70`、分块大小 32 为例，分块起点是 0、32、64；最后一块只有索引 64 到 69，所以结束位置（不包含）是 70。固定容量数组可能是 256×256，因此索引 70 虽然不属于当前 70×70 矩阵的有效区域，却不一定超出实际分配的数组。程序没有崩溃，不等于访问就是安全的。

我还理解了分块的收益和成本。分块可能改善数据复用，但也会增加循环控制开销，并改变 A、B、C 的复用方式。因此，分块不一定比原来的 `ikj` 更快。

这次正式实验共有 75 条记录，所有记录的状态都是 `PASS`，逐元素比较均为 `YES`。`n=70`、分块大小 32 的边界测试也通过了。

从 CSV 的中位数看，`ikj` 在三个矩阵规模下都明显快于 `ijk`。三种分块版本里，分块大小 64 的结果最好，但在 128 和 256 阶矩阵上仍然慢于 `ikj`。这些时间能说明本次实验的性能表现，却不能单独证明缓存未命中发生了怎样的变化。

下一步我可以继续补充不同矩阵规模的边界测试，并学习怎样结合样本波动、缓存容量和数据复用来分析分块大小。
