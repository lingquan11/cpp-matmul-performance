## 拍次约定

和 explorer 仓库对齐的是拍次，不是同一组数。

- 从 0 开始计拍。
- PE(i,j) 在第 `t = i+j+k` 拍收到第 k 对数据。i、j、k 都从 0 起，i 和 j 是 tile 里面的坐标。
- 本仓库用 Day 2：A = [[2, 1], [3, 4]]，B = [[5, 2], [1, 6]]，C = [[11, 10], [19, 30]]。这组数已经在 [`src/day02-matrix.cpp`](../src/day02-matrix.cpp) 里。
- explorer 用练习 A：[[1, 2], [3, 4]] × [[5, 6], [7, 8]] = [[19, 22], [43, 50]]。
- 两边不把矩阵改成同一组。手算表的拍次格式互相引用。

待零醛手算核对：按这个约定，2×2、K=2 时，最终值出现在 t=1 的 PE(0,0)=11，t=2 的 PE(0,1)=10 和 PE(1,0)=19，t=3 的 PE(1,1)=30。提示词里的「第 1 拍 / 第 2 拍 / 第 3 拍」我先按这些 t 理解。我和手算不一致时，以我拍的手算表为准。

## 解析式（待零醛手算核对）

这些数来自提示词里已经用公式复核过的列表，不是我跑模拟器得到的，也不是硬件计数。

- `expected_cycles(n,P) = (⌈n/P⌉)² × (n + 2P − 2)`
- 单 tile 周期 `K + 2P − 2`。2×2、K=2 时为 4 拍，利用率 50%。
- n=4、P=2：24 拍，利用率约 66.7%。
- n=64、P=8：4992 拍。

利用率先按有用乘加 `n³ / (周期 × P²)` 理解。2×2 和 n=4、P=2 都能整除，没有空间补零。n 不能整除 P 时，补零乘加算不算进 `macs`，等我手算后再定。测试在整除的两组上对 50% 和 2/3，不对其它规模编一套利用率。

缓冲读次数（`buf_reads_A`、`buf_reads_B`，以及每个 PE 上的计数）等我实现之后再填，这里不先写个数。
