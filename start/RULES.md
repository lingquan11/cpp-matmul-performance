# 学习规则（全部规则就这一页）

> 我、GPT、Muse 共用，入口和分工在根目录的 `AGENTS.md`。改规则必须由我本人批准。
> **共享文件**（`AGENTS.md`、`start/RULES.md`、`start/prompts/`、`start/templates/`、`start/scripts/`）只从 learning-workflow 仓库同步，任何 AI 不得直接修改；`progress.py --check` 会核对 `start/WORKFLOW.lock`。

## 1. 仓库三区
| 区 | 回答的问题 | 给谁看 |
|---|---|---|
| `start/` | 我该怎么开始下一次学习？（状态、路线、战役、任务卡、提示词、脚本） | 我、GPT、Muse |
| `journey/` | 我是怎么学的？（时间线、日志、笔记） | 别人 |
| `results/` | 我学成了什么？（代码、实验、结论） | 别人 |

- 给别人看的部分**必须精简**：`README.md` ≤ 40 行，`journey/README.md` ≤ 30 行，`results/README.md` ≤ 30 行，每个实验的 `README.md` ≤ 30 行，日志每行 ≤ 120 字。
- 原始材料（旧计划、对话、试错草稿）放 `journey/archive/`，不在任何 README 中展开。
- 文件和目录名用英文短横线，按内容命名。中文写在内容里。

## 2. 三栏学习
| 栏 | ID | 谁负责 | 怎么学 | 怎么算完成 |
|---|---|---|---|---|
| **阅读** | `<战役>-Rxx` | 我自己 | 读逻辑连贯的长文（教材、经典论文、作者本人的长文），**不和 AI 对话** | 读完告诉 Muse 记录；每篇附"读完应该能回答"的自测问题，不考核 |
| **编程** | `<战役>-Pxx` | GPT 带我写 | `[me]` 代码由我写，GPT 只按提示梯度引导；测试由 GPT 运行 | 机器验收（测试、校验、错误注入）全部通过 |
| **动手** | `<战役>-Hxx` | Muse | 装环境、配工具、跑测量与剖析、综合与后端、整理实验结果 | 机器验收（命令输出、报告、数据）全部通过 |

- **主线与支线**：主线 = 主教材阅读 → 编程 → 动手，三张表计入进度；支线 = 与主教材配套的现成实践课程（如 HDLBits、LeetGPU、Performance Ninja），在课程自己的网站或仓库里做，按"配合主线"一列在读完对应章节后做，**选做、不计入进度、不考核**，做完对 Muse 说"做完 <S编号>"记一行日志；卡住可以找 GPT 按提示梯度带。
- **一个战役一份主教材**：阅读表只排一本书或一个完整教程（同一作者 / 同一系列）的章节，不在几份资料之间来回切换；主教材没写到的内容才另找一篇，并在战役文件中写明原因。规范、手册、官方教程只在编程 / 动手任务里查阅，不排进阅读表。
- 编程和动手任务写明"先读"哪几篇；没读完时导师提醒一句，不阻止。动手任务里需要我解读的部分（结论、分析）由我写，Muse 只提供数据。

## 3. 战役
- 学习按"战役"推进：3–6 周，一个公开交付物。每个战役一个目录 `start/campaigns/<id>-<名称>/`：`campaign.md`（三张表）+ 编程和动手任务卡；阅读项写在表里，不单独建卡。状态汇总在 `start/ROADMAP.md`。
- 每个战役分**必做**和**加分**。到截止日以必做为准收尾，不延期、不重写计划；没做完的加分项移到 `start/IDEAS.md`。
- 战役进行中不新增计划文档。长战役每栏只先写前两张任务卡，后面的在前一张完成后再展开：只能展开表中已列的任务，验收不得弱于表中的要点，由我审核后才开工。

## 4. 状态与归档
- 唯一数据源：任务状态只在 `campaign.md` 三张表的状态列（阅读：未读 / 在读 / 读完；编程：未开始 / 进行中 / 通过；动手：未开始 / 进行中 / 完成）；战役状态只在 `start/ROADMAP.md`；当前位置在 `start/STATE.md`（三个小节，各自维护）；成果结论只在 `results/README.md` 的结论表。
- 首页进度条和成果表由 `start/scripts/progress.py` 生成，不手动修改。
- 谁做谁归档：GPT 归档编程（`journey/coding-log.md`），Muse 归档动手和阅读（`journey/hands-on-log.md`）。只改自己那一栏的文件和 STATE 小节；写之前和推送前都 `git pull --rebase`。

## 5. 代码所有权
- 任务卡中标 `[me]` 的部分（kernel、RTL、算子本体、testbench 主体）只能由我写；AI 可以提示，不能给出可直接粘贴的实现。
- 标 `[ai]` 的周边部分（构建、运行脚本、CI、作图）可以交给 AI。commit 以 `[me]` 或 `[ai]` 开头，混合时分开提交。

## 6. 事实
- 硬件参数、API 行为、论文结论必须附一手来源；没有来源的标〔未核实〕。本机事实以工具读数为准。
- 任何 AI 在提出计划或修改建议前，先看仓库现状（`git log --oneline -15`、`start/STATE.md`）。
- 每次归档检查用时：超过计划 1.5 倍时在 STATE 中提醒，由我按 `campaign.md` 的砍线顺序决定砍什么。
