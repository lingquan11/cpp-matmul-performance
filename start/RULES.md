# 学习规则（全部规则就这一页）

> 我、导师 AI、考官 AI、归档 AI、仓库助手共用。改规则必须由我本人批准；任何 AI 不得新建规则文件。

## 1. 仓库三区
| 区 | 回答的问题 | 给谁看 |
|---|---|---|
| `start/` | 我该怎么开始下一次学习？（状态、路线、战役、任务卡、提示词） | 我和 AI |
| `journey/` | 我是怎么学的？（时间线、日志、笔记、考核记录） | 别人 |
| `results/` | 我学成了什么？（代码、实验、结论） | 别人 |

- 给别人看的部分**必须精简**：`README.md` ≤ 40 行，`journey/README.md` ≤ 30 行，`results/README.md` ≤ 30 行，每个实验的 `README.md` ≤ 30 行，log 每行 ≤ 120 字。
- "边界与局限"每个实验最多 3 条，只写在该实验 README 的"边界"一节，其他地方不重复。
- 原始材料（对话记录、补缴说明、维护记录、旧计划、没做的脚手架）放 `journey/archive/`，不在任何 README 中展开。
- 文件和目录名用英文短横线，按内容命名；不用 `dayNN`、`YYYY-MM-DD` 占位符、`gpt`、`V0x`。中文写在内容里。

## 2. 战役
- 学习按"战役"推进：3–5 周，一个公开交付物。每个战役一个目录 `start/campaigns/<id>-<名称>/`，内含 `campaign.md` 和任务卡；状态汇总在 `start/ROADMAP.md`。
- 每个战役分**必做线**和**加分线**。到截止日以必做线为准收尾，不延期、不重写计划；没做完的加分线移到 `start/IDEAS.md`。
- 战役进行中不新增计划文档。长战役只先写前两张任务卡，后面的卡在前一张通过后再展开：只能展开 `campaign.md` 已列的任务，验收不得弱于其中的验收要点，由我审核、提交后才开工。

## 3. 状态与归档
- `start/STATE.md` 是唯一的当前状态（≤ 30 行）。每次学习只需读它和当前任务卡。
- 每次学习结束，用 `start/prompts/archiver.md` 归档：更新 STATE、追加 log；任务通过时更新 `results/`；里程碑时更新 `journey/README.md` 的时间线。

## 4. 验收（三层，越靠前权重越大）
1. **机器验收**（必须）：测试、校验、数字、截图。验收条件在开工前写进任务卡，之后任何 AI 不得修改。
2. **闭卷解释**（我产出）：不看资料，手写推导或口述 3 分钟，拍照或录音存档。
3. **考官 AI 提问**（辅助）：在新会话中用 `examiner.md` 进行，不给它看教学对话；只负责找漏洞，不能单独判定通过。

## 5. 代码所有权
- 任务卡中标 `[me]` 的部分（kernel、RTL 模块、算子本体）只能由我写；AI 可以提示，不能给出可直接粘贴的实现。
- 标 `[ai]` 的周边部分（构建、计时框架、画图、CI）可以交给 AI。commit 以 `[me]` 或 `[ai]` 开头，混合时分开提交。

## 6. 事实
- 硬件参数、API 行为、论文章节必须附一手来源；没有来源的标〔未核实〕。本机事实以工具读数为准，并保留截图。
- 任何 AI 在提出计划或修改建议前，先看仓库现状（`git log --oneline -15`、`start/STATE.md`）。

## 7. 节奏
- 每次学习：贴 STATE 和任务卡给导师 → 3 个回顾问题 → 做任务 → 跑验收 → 归档。
- 每两周复盘一次（`reviewer.md`）。实际用时超过计划 1.5 倍时，按 `campaign.md` 的砍线顺序砍加分线。
