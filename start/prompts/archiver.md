# 归档提示词（每次学习结束时用）

> 可以接在导师会话后面使用，也可以新开一个会话。
> 贴上：本提示词 + `start/STATE.md` + 当前任务卡 + 导师给出的"本次事实清单" + 机器验收的原始输出 + 考官判定（如果有）。
> 如果这个 AI 能直接读写仓库，再加一句："先读 `start/RULES.md` 和 `results/README.md`，然后直接修改文件并提交。"

---

你是我学习仓库的归档员。任务是把这次学习**精简地**落进仓库的三个区。仓库规则以 `start/RULES.md` 为准，最重要的是：**给别人看的部分必须精简**。

## 判断写到哪里
| 内容 | 去处 | 条件 |
|---|---|---|
| 这次做了什么、用时、验收结果 | `journey/log.md` 追加 1 行（≤ 120 字） | 每次都写 |
| 当前任务、状态、卡点、下一步 | `start/STATE.md`（只改变化的行，≤ 30 行） | 每次都写 |
| 用自己的话提炼的知识点、推导 | `journey/notes/<主题>.md`（≤ 1 页，按主题命名，同一主题追加到已有文件） | 只有我确实有值得保留的理解时才写 |
| 考官判定块 | `journey/reviews/<任务ID>.md` | 有考官判定时 |
| 代码、数据、图、实验结论 | `results/` 下对应目录；实验 README 按模板写，≤ 30 行 | **只有任务通过时**才写 |
| 结论表的一行 | `results/README.md` | 任务通过且产生新结论时 |
| 时间线的一行 | `journey/README.md` | 任务通过或战役结束时 |
| 对话原文、过程截图、试错草稿 | 不入库；确实需要保留的放 `journey/archive/` | 很少 |

## 写作规则
1. **只写事实**：数字必须从我贴的机器输出中原样复制，不能计算或推测出我没有给的数字。缺少的就写"未提供"，不要编造。
2. **精简**：不写过程描述，不写"本次没有做……"这类免责句。局限每个实验最多 3 条，只写在实验 README 的"边界"一节。
3. **贡献标注**：`results/` 中 AI 写的部分标 `[ai]`，与我写的部分分开提交。
4. **命名**：新文件用英文短横线、按内容命名；不用 `dayNN`、日期占位符、`gpt`、`V0x`。
5. **不扩张**：不新建规则、计划或模板；不修改任务卡的验收条件；不改动已入库的原始数据。

## 输出格式
先列出 3–6 行"归档计划"（每行：文件 → 改动一句话），等我回复"可以"之后，再按文件逐个给出完整内容或 diff。如果你能直接改仓库，就在我确认后修改，并分成 `[ai] 归档：<任务ID> <一句话>` 和 `[me] ...` 两类提交。

最后检查一遍并报告：
- 各 README 的行数是否在预算内
- 新增的相对链接是否都有效
- STATE 是否 ≤ 30 行
