# 归档（我说"结束"或考核结束后自动执行）

把这次学习**精简地**落进仓库，并同步所有联动文件。最重要的规则：**给别人看的部分必须精简**（预算见 `start/RULES.md` §1）。

## 同步清单（按顺序逐项执行，不适用的跳过）

**每次都做**
1. `journey/log.md` 追加 1 行（≤ 120 字），格式：`日期 | 实际用时 | 任务ID | 做了什么 | 机器验收: ✓/✗/未跑 | 闭卷: ✓/未做 | 考官: 通过/不通过/未考 | 卡点`。用时问我，我说不出就写"未知"；任务 ID 用完整形式（如 `C0-T03`）。
2. 当前 `campaign.md` 必做线表中该任务的"状态"列：第一次学习 → `进行中`；机器验收全部 ✓ 但考官没通过 → `待考官`；考官通过，或任务卡写明"不考官"且机器验收全部 ✓ → `通过`。
3. `start/STATE.md`：更新日期、上次停在哪、未解决的问题、下一步（≤ 30 行，只改变化的行）。
4. 用时检查：本战役已用时（log 中本战役各行之和）超过已通过任务和当前任务计划用时之和的 1.5 倍时，在 STATE 的"未解决的问题"中写一行：`用时超出：建议按砍线顺序砍 <ID>，需要我决定`。不要替我砍。

**有考官判定时**
5. 把判定块原样写入 `journey/reviews/<任务ID>.md`（多次考核就追加）。

**任务通过时**
6. `results/`：放入代码、数据和图；实验 README 按 `start/templates/experiment-readme.md` 写（≤ 30 行）。
7. `results/README.md`：在 `<!-- results:start -->` 与 `<!-- results:end -->` 之间的结论表中加一行。首页的成果表会由脚本从这里自动生成，**不要直接改首页的成果表**。
8. `journey/README.md`：时间线加一行。
9. STATE 指向下一个任务；如果它的任务卡还不存在，在"下一步"中写"下次开始时起草 <任务ID> 的任务卡"。
10. 我在学习中用自己的话说清楚的理解，写进 `journey/notes/<主题>.md`（≤ 1 页，同一主题追加到已有文件）。没有就不写。

**战役结束时**（必做线全部通过，或到了截止日）
11. `start/ROADMAP.md` 中该战役的状态改为 `完成`；按 `campaign.md` 的"收尾定义"执行（打 tag 等）；journey 时间线加一行。
12. STATE 指向下一个战役。新战役的 `campaign.md` 按 ROADMAP 中的那一行和模板起草，下次"开始学习"时给我审核。

**最后**
13. 运行 `python start/scripts/progress.py`：它会更新首页的进度条和成果表，并检查行数预算、log 长度和相对链接。有 ✗ 就修到全部 ✓。
14. 提交：我写的代码用 `[me] <一句话>`，其余用 `[ai] 归档：<任务ID> <一句话>`，分开提交。推送到当前分支；推送失败就告诉我原因。
15. 用 3–5 行告诉我：改了哪些文件、进度条现在是多少、下次从哪里开始。

## 写作规则
- **只写事实**：数字从机器输出原样复制，不计算或推测我没有给出的数字；缺少就写"未提供"。
- **精简**：不写过程描述，不写"本次没有做……"这类免责句；局限每个实验最多 3 条，只写在实验 README 的"边界"一节。
- **命名**：新文件用英文短横线、按内容命名；不用 `dayNN`、日期占位符、`gpt`、`V0x`。
- **不扩张**：不新建规则、计划或模板；不改任务卡的验收条件；不改已入库的原始数据。对话原文、试错草稿不入库。
