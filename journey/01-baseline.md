# 第 1 章：正确性与测量

> 先把矩阵乘法算对，再定好怎么测它有多快。后面每一章的数字都建立在本章的校验和计时方法上。

## 要点
- 定义：`C[i][j]` 是 A 的第 i 行与 B 的第 j 列逐项相乘再累加；朴素三重循环是 O(n³)，边长翻倍，计算量变 8 倍（计算量，不是耗时）
- 正确性：零矩阵、单位矩阵、校验和、逐元素比较，各自能证明什么、不能证明什么
- 计时：`std::chrono::steady_clock`，只包住清零和乘法；先预热，每个配置测 5 次
- 边界检查：固定容量 `MAX_N` 与实际规模 `n` 分开，非法参数在访问数组之前就拒绝

## 讲义
[我的笔记：正确性与计时](notes/correctness-and-timing.md)，按日期三篇：
- Day 1：手算 2×2 乘积中的 `C[0][0]`，再用程序算出同一个数
- Day 3：零矩阵检查、O(n³) 的来由、第一版测量方案
- Day 4：可输入阶数、边界检查、`steady_clock` 计时、校验和的局限

## 练习
1. **手算一个元素**：A = [[2, 1], [3, 4]]、B = [[5, 2], [1, 6]]，先手算 `C[0][0]`，再写程序只算它、确认一致，最后加上 i、j 循环算出完整 2×2 结果
2. **用特殊矩阵检查**：B 换成零矩阵、再换成单位矩阵（结果应等于 A），每次先写下预期再运行。思考：两个结果矩阵的校验和相同，能说明它们完全一样吗？
3. **给乘法计时**：n 从输入读取，不在 `1..MAX_N` 内就拒绝；`steady_clock` 只包住清零和乘法，初始化、校验、输出放在计时外；n = 64、128、256 各测 5 次，保留每次的原始耗时
4. **跑仓库的正确性测试**：在仓库根目录运行 `bash results/tests/smoke.sh`。它编译 `results/src/` 下全部程序、运行分块正确性测试，不计时；n = 0、n = 257 这类非法参数必须以退出码 2 被拒绝
