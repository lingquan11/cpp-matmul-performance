## Day 1：我先算了一个元素

2026-10-22，北京时间。我花了 30 分钟，记在每日任务记录里。这一天我只算两个 2×2 矩阵乘积里的 C[0][0]。程序输出是 11，和我手算的一样。

A = [[2, 1], [3, 4]]
B = [[5, 2], [1, 6]]

C[0][0] 是 A 的第 0 行和 B 的第 0 列乘完再加起来：

C[0][0] = A[0][0] × B[0][0] + A[0][1] × B[1][0]
        = 2 × 5 + 1 × 1
        = 11

我把 c00 先写成 0，不然第一次 += 没有起点。k 从 0 走到 1，两项乘积都盖住了，下标也没越界。A[0][k] 一直是 A 的第 0 行，B[k][0] 一直是 B 的第 0 列。用 += 是因为要累加，不能用一次赋值把前一项盖掉。cout 打出 11 然后换行。

程序在 `src/day01-matrix.cpp`，结果放在变量 c00 里。完整的 2×2 我留到 Day 2，写在 `src/day02-matrix.cpp`。下一步我打算加上行和列的循环，把四个元素都算出来再打印。这份笔记就停在 Day 1。

### 我怎么理解 O(n³)

我想的是两个 n×n 方阵的朴素三重循环。i 选结果的一行，有 n 个值。i 固定以后，j 选结果的一列，也是 n 个值，所以 i、j 的组合有 n² 个。每一对 i、j 再用 k 走 n 个乘积并累加，得到一个结果元素。

最内层乘积累加的总次数，主要项是 n × n × n = n³。如果一次乘法、一次加法和一次下标访问都按常数成本算，时间复杂度是 O(n³)，也可以写成 Θ(n³)。把结果初始化是 O(n²)，不改变这个阶。

我一开始说成“i 有 n 次，j 有 n 的平方，k 有 n 的三次方”。现在我分得清：每一层自己都是 n 次，n² 和 n³ 是把外层乘进去之后的次数。

边长从 n 变成 2n 时，(2n)³ / n³ = 8。计算量变成原来的 8 倍。我当时说“8到64，正增长8倍”，意思是从 8 变成 64，是原来的 8 倍。这是计算量，不是我已经测到的耗时倍数。耗时倍数等我测完再写。

### 我当天写的测量方案

我想比较同一段朴素乘法在不同规模下要跑多久。规模用 64×64、128×128、256×256。编译用 Release，并把编译器、版本和实际优化选项记下来，因为光写一个 Release 看不出开了什么优化。环境记下 CPU、操作系统、内存和电源模式，后台尽量别乱动。输入固定、能复现，取值别把我用的整数类型乘溢出。正式测量前先预热，预热不进统计。每种规模正式测 5 次，每次的原始耗时都留着，再算平均。时钟用单调的，比如 C++ 的 steady_clock。计时只包住矩阵乘法本身。分配内存、准备输入、把结果清零、打印和正确性检查都放在计时外面。测量前后我要检查结果，计时结束之后还得用一下这个结果，免得编译器把计算删掉。时间单位统一，相邻规模的平均耗时拿来比，波动留在原始数据里。

如果程序是往 C 里累加的，每次正式测量前我要把 C 清零，不然上一次会污染下一次。单次短到接近计时精度时，我就改成在样本里重复，并把怎么换算记下来。

我之所以不只测一次，是因为后台任务和 CPU 频率会晃。把每次都留下来，我才能看见晃了多少。平均通常比单次更像样，但也不能保证把偏差都消掉。

cout 放在计时外面，是因为打印还有格式化和输出的开销。我想测的是乘法本身。

边长翻倍时计算量变成 8 倍。实际耗时比还会受缓存、编译优化、系统负载和测量误差影响，这个得靠后面的实验看。

## Day 4 学习笔记

今天我把固定规模的矩阵乘法改成可以输入阶数，并加上了边界检查。

`MAX_N` 是数组最多能放多大，`n` 是这次实际算多大。A 和 B 用公式填，再用三重循环算 C。`n = 0` 时循环进不去，但不符合这次的要求。`n = 257` 超过容量，不检查就可能越界。

计时用 `std::chrono::steady_clock`。计时包住 C 清零和矩阵乘法。A、B 初始化、校验和、正确性检查、输出都在外面。

校验和是把 C 的每个元素加起来，得到一个数。很多结果变了它能看出来。不同矩阵也可能加出同一个和，所以它单独证明不了每个元素都对。以后可以在计时结束后逐个元素对参考结果。

正式样本是 64、128、256，每个规模 5 次。截图转录 15 条都是 PASS。128 阶第 5 次明显偏高，原值留着。分析在 [`supplements/day04-day05-n128-high-samples.md`](https://github.com/lingquan11/cpp-matmul-performance/blob/archive-2026-11-23/journey/archive/notes/supplements/day04-day05-n128-high-samples.md)，唯一根因仍未知。学习用时后来补记为 2 小时。
