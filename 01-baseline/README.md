# 第 1 章：正确性与测量

> 先把矩阵乘法算对，再定好怎么测它有多快。后面每一章的性能数字，都建立在这一章的校验和计时方法上。

## 本章收获
写出一个算对的朴素矩阵乘法，用零矩阵、单位矩阵和逐元素比较确认它是对的，并按固定口径（单调时钟、只包住乘法、重复取样）测出耗时。

## 知识点地图
1. 矩阵乘法的定义：`C[i][j]` 是 A 的第 i 行与 B 的第 j 列逐项相乘再累加
2. 朴素三重循环与 O(n³)：边长翻倍，计算量变成 8 倍（这是计算量，不是耗时）
3. 正确性检查：零矩阵、单位矩阵、校验和、逐元素比较，各自能证明什么、不能证明什么
4. 计时口径：`std::chrono::steady_clock`，计时只包住清零和乘法，预热，每个配置重复 5 次
5. 边界检查：固定容量 `MAX_N` 与实际规模 `n`，越界的参数要在访问数组之前拒绝

## 动手实践

### 任务一：手算一个元素
1. 取 A = [[2, 1], [3, 4]]、B = [[5, 2], [1, 6]]，手算 `C[0][0]`
2. 写程序只算 `C[0][0]`，确认输出和手算一致（对照笔记 01）
3. 加上 i、j 两层循环，算出完整的 2×2 结果

### 任务二：用特殊矩阵检查正确性
1. 把 B 换成零矩阵，先写下预期输出，再运行确认
2. 把 B 换成单位矩阵，结果应该等于 A
3. 思考：两个结果矩阵的校验和相同，能不能说明它们完全一样？

### 任务三：给乘法计时
1. 让 n 从输入读取，n 不在 `1..MAX_N` 内时拒绝运行
2. 用 `steady_clock` 只包住清零和乘法；初始化、校验、输出都放在计时外
3. n = 64、128、256 各测 5 次，每次的原始耗时都保留

### 任务四：跑一遍仓库里的正确性测试
在仓库根目录运行：
```bash
bash results/tests/smoke.sh
# 观察：编译 results/src/ 下的全部程序，运行分块正确性测试，不运行任何计时
# 观察：n = 0、n = 257 这类非法参数必须以退出码 2 被拒绝
```
